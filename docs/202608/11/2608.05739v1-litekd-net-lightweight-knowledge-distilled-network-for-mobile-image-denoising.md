## 摘要
移动图像去噪既需要良好的恢复质量，又需要较低的计算成本。此外，收集大规模的低质量-地面真值干净图像对是令人烦恼的。因此，我们提出了LiteKD-Net，一种用于移动图像去噪的轻量级知识蒸馏网络。首先，与应用于相机的流水线相比，通过添加像素串扰的物理引导噪声模拟流水线生成成对的训练数据。接下来，我们将Real-ESRGAN适应于同分辨率去噪，并基于深度可分离卷积使用Lite-RRDB块构建轻量级学生网络。第三，应用特征级知识蒸馏将教师的恢复能力迁移到学生网络，而不引入额外的推理成本。在真实世界数据集上的实验表明，我们的模型在保持良好的恢复质量的同时，实现了运行时间的大幅减少和推理速度的提高。与SwinIR相比，我们的模型在所有指标上也达到了最佳。这些结果表明，LiteKD-Net在恢复质量和计算效率之间提供了很好的权衡。

## Abstract
Mobile image denoising requires both good restoration quality and low computational cost. In addition, it's annoying to collect large-scale LQ-GT clean pairs. As a result, we propose LiteKD-Net, a lightweight knowledge-distilled network for mobile image denoising. First, a physics-guided noise simulation pipeline generates paired training data by adding pixel crosstalk compared with pipelines applied to cameras. Next, we adapt the Real-ESRGAN to identity-resolution denoising and construct a lightweight Student using Lite-RRDB blocks based on depthwise separable convolutions. Third, feature-level knowledge distillation is applied to transfer the Teacher's restoration capability to the Student without introducing additional inference cost. Experiments on real-world datasets show that our model reaches great reduction in runtime and increase in the inference rate with good restoration quality. Our model also reaches the best in all metrics compared with SwinIR. These results indicate that LiteKD-Net provides a great trade-off between restoration quality and computational efficiency.

## 1. 核心问题与整体含义（研究动机与背景）

- **移动端成像的固有瓶颈**：手机传感器尺寸小、单像素面积小，单位曝光捕获的光子数少，导致信噪比先天偏低。提高传感器增益又会放大噪声、带状条纹等退化，因此去噪是移动图像恢复的关键环节。
- **高容量模型难以落地**：主流深度去噪网络参数动辄数千万、浮点运算量达数十亿级别，在移动硬件上面临高延迟、高能耗、内存占用过大的问题。云端处理虽可缓解本地计算压力，但引入通信延迟、带宽成本和隐私风险。
- **配对训练数据难以获取**：在相同场景下拍摄内容一致但噪声不同的图像对十分困难（受物体运动、光照变化和机内处理流程影响），而纯合成高斯噪声无法真实反映 CMOS 传感器的信号相关性与结构化噪声。
- **解决思路**：论文提出 LiteKD-Net，将"物理引导的噪声模拟 + 轻量化架构设计 + 特征级知识蒸馏"整合为一个统一框架，力求在恢复质量与计算效率之间取得良好平衡。

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 整体框架
论文提出三组件统一框架：**NSP 噪声模拟流水线**构建配对训练数据 → **Lite-RRDB 轻量学生网络**实现高效去噪 → **Noise-KD 特征级知识蒸馏**从冻结的 Heavy Teacher 迁移恢复能力。

### 2.2 Noise Simulation Pipeline（NSP）
- 在**约线性化 sRGB 域**中模拟传感器噪声（而非 RAW 域），流程为：sRGB → gamma 展开（γ=2.2）→ 线性 RGB 域模拟各类噪声 → 裁剪 → 逆 gamma 变换回 sRGB。
- 依次模拟四类噪声：**光子散粒噪声**（泊松分布，信号相关）、**Tukey–Lambda 重尾读出噪声**、**行噪声**（每行共享高斯偏移）、**量化噪声**（均匀分布）。
- **核心创新——像素串扰（Pixel Crosstalk）建模**：用 3×3 通道内卷积核实现相邻像素间的局部空间相关。核权重之和为 1（约保持亮度），默认强度 ρ=0.03，中心像素占 0.85，15% 扩散至邻域。论文通过隔离实验（图 2）验证了串扰引入的是空间相关噪声而非独立噪声。

### 2.3 Lite-RRDB 轻量模块
- 将 Real-ESRGAN 中标准 RRDB 替换为 Lite-RRDB：每个 Lite-RDB 内**去除密集连接路径**，5 层改为顺序执行，特征宽度固定 64 通道；标准 3×3 卷积替换为**深度可分离卷积**（3×3 深度卷积 + 1×1 逐点卷积）。
- 保留局部残差连接与残差缩放（×0.2），以及 RDB 间的外部残差连接，维持残差嵌套结构以稳定训练。
- 标准卷积与深度可分离卷积的参数量对比：标准为 k²·Cin·Cout，深度可分离为 k²·Cin + Cin·Cout，显著降低参数量。

### 2.4 Noise-KD 知识蒸馏
- 先训练同分辨率（无上采样模块）的 Heavy Teacher（基于 Real-ESRGAN，23 个 RRDB），收敛后**冻结全部参数**。
- 训练学生时，将同一噪声图像分别送入教师和学生网络，取 backbone 输出的特征图计算 **MSE 特征蒸馏损失**。
- 学生总损失 = L1 像素重建损失 + λper·LPIPS 感知损失 + λKD·LKD 蒸馏损失。
- **教师仅在训练阶段使用，推理时完全丢弃**，不增加任何推理期参数或计算量。

## 6. 主要结论与发现

- **效率大幅提升**：相较 Real-ESRGAN 基线，LiteKD-Net 将模型参数量从 16.70M 压缩至 1.67M（约 **10 倍缩减**），MACs 从 1.17T 降至 108.28G（约 **10.8 倍缩减**），FLOPs 从 2.35T 降至 216.55G，推理速度从 6.72 FPS 提升至 11.98 FPS（约 **2 倍提速**）。

- **知识蒸馏有效**：消融表明 Lite-RRDB 单独使用质量下降明显（PSNR 37.24），加入 Noise-KD 后恢复至 37.91，验证了特征级蒸馏对恢复能力的有效迁移。
- **核心结论**：LiteKD-Net 在恢复质量与计算效率之间实现了出色权衡，适合移动端部署。

## 7. 优点

1. **噪声建模更贴近实际**：在物理噪声模拟（光子散粒噪声 + 重尾读出噪声 + 行噪声 + 量化噪声）基础上，首次引入像素串扰建模，拟合了移动传感器中相邻像素的局部空间相关性，比纯合成高斯噪声更真实。
2. **轻量化设计巧妙**：Lite-RRDB 去除密集连接而不破坏残差嵌套结构，用深度可分离卷积替代标准卷积，在极小的参数量下保留足够表达能力。
3. **知识蒸馏不增加推理成本**：特征级蒸馏只在训练阶段生效，推理时无需额外开销，是典型的"训练贵一点、推理省很多"设计。
4. **评估体系完善**：同时覆盖有参考、无参考和效率三类指标，且效率指标从参数、FLOPs、延迟、内存等多维度度量，对移动部署场景有较好指导意义。
5. **方法具有通用性**：NSP、Lite-RRDB 和 Noise-KD 三个组件可独立替换或组合，为后续移动端图像恢复研究提供了可复用的模块化方案。

## 8. 不足与局限

1. **噪声模拟仍是近似**：方法操作在近似线性化 sRGB 域而非真实 RAW 域，未建模完整的相机成像链路（去马赛克、白平衡、色彩校正、色调映射、相机特定非线性处理等），其物理保真度存在天花板。
2. **参数固定缺乏标定**：NSP 的所有噪声参数（K、λ、σTL、σr、ρ 等）为固定值，未按具体相机型号标定，对不同手机的传感器特性泛化能力有限。
3. **对比基线不足**：仅与 Real-ESRGAN 和 SwinIR 对比，缺乏与现有移动端去噪方法（如 LPIENet、MOFA 等）和经典轻量去噪模型的对照，验证说服力受限。
4. **推理实测缺失**：效率指标基于实验室 GPU 环境测得，论文未提供在真实移动端硬件（如手机 SoC、NPU/DSP）上的延迟和功耗实测数据，对"mobile deployment"的论证支撑不足。
5. **训练数据可复现性存疑**：训练集由作者自行构建（混合自建模拟与真实数据），未公开完整的数据划分和构建细节，其他研究者难以复现完全一致的实验条件。
6. **GPU 信息缺失**：仅提及 RTX 3090 且未报告数量与训练总时长，算力成本不透明，对工程可行性评估造成障碍。
7. **消融细节不完整**：未分别测试不同的蒸馏权重 λKD、串扰强度 ρ 等超参数敏感性，对 NSP 各噪声分量（如单独移除行噪声或串扰）的贡献缺乏逐项分析。
